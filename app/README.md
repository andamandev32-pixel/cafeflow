หน้าจอ 9 หน้า (พนักงาน 7 + คีออสก์ลูกค้า 1 + จอแสดงคิว 1) ที่ทำงานเชื่อมกันจริง สร้างบน `design-system-2/`
ตามสเปก [`CafeFlow_System_Design_AndamanTech.md`](../CafeFlow_System_Design_AndamanTech.md)
เมนูถอดจากป้ายหน้าร้านจริง

> **หน้าชุดนี้ทำงานได้สองโหมด** เลือกอัตโนมัติจากคนที่เสิร์ฟมัน (ดู `js/cf-config.js`)

> · **`api`** — ข้อมูลจริงอยู่ที่เซิร์ฟเวอร์ในร้าน (PostgreSQL) เปิดผ่าน `cafeflow-api`
>   ดูวิธีติดตั้งและดูแลที่ [`../ops/README.md`](../ops/README.md)

> **`design-system-2/` ไม่ถูกแก้แม้แต่ไบต์เดียว** — หน้าตาแบบ ServiceFlow มาจาก
> `app/css/ds-cafeflow-theme.css` ที่ทับโทเคนทีหลัง ถอดไฟล์นี้ออกแล้วกลับเป็น MediCore ทันที
> (ยืนยันได้ด้วย `diff -r design-system/design-system design-system-2`)

## ลองให้เห็นว่ามันเชื่อมกันจริง

1. เปิด `cashier.html` และ `kds.html` **คนละแท็บ**
2. ที่แคชเชียร์ กดการ์ดออเดอร์ที่ "รอเงินสด" → ใส่จำนวนเงิน → รับชำระ
3. ตั๋วจะโผล่บนบอร์ดครัวในอีกแท็บ **ภายใน ~1.5 วินาที โดยไม่ต้องรีเฟรช**
4. กด "พร้อมเสิร์ฟ" ให้ครบทุกสถานี → ออเดอร์ย้ายไปแท็บ "พร้อมรับ" ของแคชเชียร์ (§21)
5. `dashboard.html` และ `closing.html` ขยับยอดตาม

ลองเรื่องอื่น:
- `menu.html` → **เพิ่มรายการสินค้า** → เปิด-ปิดสวิตช์ ร้อน/เย็น/ปั่น แล้วดูราคาแยกกันคนละช่อง
  · สลับ "ดูตัวเลือกของแบบ" เป็น *ปั่น* แล้วกลุ่มน้ำแข็งหายไปพร้อมคำอธิบายว่าทำไม (§11)
- ในฟอร์มเดียวกัน กด **แก้ไขตัวเลือก** → drawer ซ้อน → กดกลับ → ค่าที่พิมพ์ไว้ยังอยู่ครบ
- `orders.html` → เลือกออเดอร์ → **ใบเสร็จรับเงิน** → สลับ 58/80 มม. เทียบกันก่อนพิมพ์
- ใน console: `CFOrders.transition(id, 'COMPLETED')` จากสถานะ `WAITING_CASH` → ถูกปฏิเสธพร้อมเหตุผล

**คีออสก์ (ลูกค้าสั่งเอง)** — เปิด `kiosk.html` ตรงได้เลย ไม่ต้องล็อกอิน
ครั้งแรกจะให้เลือกเครื่อง KIOSK-01/02/03 แล้วจำไว้ (หรือระบุด้วย `?device=KIOSK-02`)

Flow แบบร้าน QSR จริง: **แตะเพื่อเริ่ม → กินที่ร้าน/กลับบ้าน → เมนู → รายละเอียด →
แนะนำเมนูเพิ่ม (ครั้งเดียว) → ตะกร้า → ชำระเงิน → เลขคิว** · สั่งกาแฟหนึ่งแก้วจบใน 5 แตะ
ปุ่มย้อนกลับอยู่ตำแหน่งเดิมทุกหน้า ตะกร้าเห็นตลอดไม่เคยหาย

ลองครบวง: `kiosk.html` สั่งของสองสถานี → ชำระเงินสด → ได้เลขคิว →
เปิด `cashier.html` อีกแท็บ ออเดอร์อยู่ในแท็บ "รอเงินสด" → รับชำระ → ตั๋วขึ้น KDS ทั้งสองสถานี

รีเซ็ตข้อมูล: ปุ่ม **รีเซ็ตข้อมูลตัวอย่าง** บนหน้าภาพรวม หรือเปิด `dashboard.html?reset=1`

### ลำดับการโหลดที่ห้ามสลับ

CSS — ธีมต้องอยู่**หลังทุกไฟล์ของ design system** ไม่ใช่แค่หลัง `ds-tokens.css`
เพราะนอกจาก remap โทเคนแล้ว มันยังต้องทับสีที่ hard-code ไว้ใน `ds-navbar.css` / `ds-landing.css`

JS — `cf-nav.js` ต้องอยู่**หลัง** `ds-navbar.js` และเรียก `DSNavbar.configure()` ที่ top level
(ไม่ใช่ใน `DOMContentLoaded`) เพราะ `ds-navbar.js` ลงทะเบียน `init()` ไว้กับ event นั้นแล้วตั้งแต่ตอนโหลด

## คีออสก์: แนวตั้ง/แนวนอน และรูปสินค้า

**เป้าหมายฮาร์ดแวร์** จอสัมผัส 21–32 นิ้ว Full HD — ผืนผ้าใบ 1080×1920 / 1920×1080 คงที่
แต่ขนาดกายภาพต่างกันเกือบ 1.5 เท่า จอ 21.5 นิ้วคือกรณีคับที่สุด (~102 PPI)
ทุกขนาดในหน้านี้เขียนเป็น `calc(var(--u) * N)` โดย `--u` ผูกกับความกว้าง**เวที** ไม่ใช่หน้าต่าง
พื้นที่กดขั้นต่ำ 54px (13 มม. ที่จอ 21.5") ปุ่มหลัก 76px และ**ปุ่มที่ต้องกดอยู่ครึ่งล่างของจอเสมอ**
เพราะส่วนบนของจอ 32 นิ้วแนวตั้งเอื้อมยากสำหรับคนตัวเล็กและผู้ใช้รถเข็น

⚠️ `cf-kiosk.css` **ห้ามมี `@media (max-width:…)`** — media query วัดหน้าต่าง แต่เวทีแนวตั้ง
เป็นลูกที่ถูก letterbox ไว้ ค่าที่วัดได้จะโกหก สลับด้วย `body.cfk-portrait` / `.cfk-landscape` เท่านั้น

**ตั้งค่าจากหลังบ้าน** ปุ่ม "ตั้งค่าคีออสก์" บนหน้าภาพรวม (หรือ `dashboard.html?kiosk=1`) —
แนวจอ · ขนาดจอ 21/24/27/32 นิ้ว · รูปแบบการรับสินค้า · หน้าแนะนำเมนู · รูปภาพ · เวลาต่าง ๆ
**รูปแบบการรับสินค้า** มี 3 แบบ — ถามลูกค้า / กินที่ร้านอย่างเดียว / กลับบ้านอย่างเดียว
สองแบบหลังคีออสก์จะข้ามหน้าคำถามไปที่เมนูทันที (4 แตะจบ) และบันทึก `diningOption` ให้ตรงตามจริง
บันทึกแล้ว**เครื่องคีออสก์ที่เปิดอยู่จะพลิกจอเองภายในไม่กี่วินาที ไม่ต้องรีเฟรช**
· ดูเร็ว ๆ ได้ด้วย `kiosk.html?o=landscape` (ชั่วคราว ไม่บันทึก)

**รูปสินค้า** โปรเจกต์ไม่มีไฟล์รูป จึงใช้ภาพวาด SVG 13 แบบใน `cf-kiosk-art.js`
เลือกอัตโนมัติจาก **ชื่อสินค้า → หมวด × แบบเสิร์ฟ** (กดร้อน/เย็น/ปั่นแล้วรูปเปลี่ยนตาม)
ร้านที่มีรูปถ่ายจริงใส่ `imageUrl` ได้ที่หน้าจัดการเมนู — **ลิงก์ตายแล้วตกกลับไปภาพวาดเอง
เพราะ `<svg>` วางซ้อนรออยู่ใน DOM แล้ว ไม่ใช่ตรรกะใน JS** คีออสก์จึงไม่มีวันขึ้นรูปแตก

## จับคู่อุปกรณ์ (§30)

**เฉพาะโหมด `api`** — คีออสก์ต้องถูกผู้จัดการจับคู่ก่อนจึงจะสั่งออเดอร์ได้

1. หน้าภาพรวม › **อุปกรณ์ในเครือข่าย** › กด **จับคู่** ที่เครื่องที่ต้องการ → ได้รหัส 6 หลัก อายุ 10 นาที
2. ไปที่เครื่องคีออสก์ กรอกรหัส → เครื่องได้ token เก็บใน cookie httpOnly (JavaScript แตะไม่ได้)
3. รหัสใช้ได้ครั้งเดียวและแสดงครั้งเดียว — ปิดหน้าต่างไปแล้วต้องขอใหม่

⚠️ **header `X-CF-Device` ใช้ตัดสินสิทธิ์ไม่ได้** เป็นสิ่งที่ client ประกาศเอง ใครก็ปลอมได้
ตัวตนของอุปกรณ์มาจาก cookie ที่เซิร์ฟเวอร์ออกให้ตอนจับคู่เท่านั้น
ก่อนมีกลไกนี้ ใครที่ต่อ Wi-Fi ร้านเปิด `kiosk.html` แล้วสั่งออเดอร์เข้าคิวครัวได้จริง

คีออสก์ที่จับคู่แล้วก็ยัง**ทำได้แค่สิ่งที่ลูกค้าทำ** — สร้างออเดอร์และส่งไปรอชำระเท่านั้น
สั่งจ่ายเงินเอง กดสถานีพร้อม หรือแก้เมนู ไม่ได้ทั้งหมด

โหมดเดโมยังเลือกเครื่องเองจากรายการเหมือนเดิม เพราะไม่มีของจริงให้ปลอมแปลง

## ตรวจสลิปด้วยกล้องคีออสก์ (§14 §17)

**เฉพาะโหมด `api`** — หน้า "สแกนเพื่อชำระเงิน" มีทั้ง QR และกล้องในหน้าเดียว
ลูกค้าโอนเสร็จแล้วยกหน้าจอสลิปขึ้นหน้ากล้อง ระบบจับสลิปเอง (จาก mini-QR บนสลิป) ถ่ายเอง แล้วส่งให้เซิร์ฟเวอร์ตรวจ

1. ติดตั้งไฟล์ภาษาของ OCR ครั้งเดียว: `cd api && npm run fetch-tessdata` (→ `data/tessdata/`)
2. ตั้งค่าที่หน้าภาพรวม › ตั้งค่าคีออสก์ › **ตรวจสลิปด้วยกล้องคีออสก์**
   - `ให้แคชเชียร์ยืนยัน` (ค่าเริ่ม) — ผ่านกฎแล้วยังรอคนกดยืนยัน
   - `ผ่านแล้วส่งครัวเลย` — ผ่านครบกฎ → PAID และส่งเข้าครัวทันที
   - `ปิดกล้อง` — กลับไปใช้ปุ่ม "โอนแล้ว" (ส่งให้แคชเชียร์ตรวจ)

กฎ: ยอดตรง · เวลาโอนหลังออก QR · ไม่เกินเวลาหมดอายุ (+3 นาที) · เลขอ้างอิงไม่ซ้ำ ([shared/cf-slip-rules.js](../shared/cf-slip-rules.js))
อ่านไม่ออกหรือไม่ผ่าน → ให้ลูกค้าถ่ายใหม่ได้ 3 ครั้ง แล้วส่งแคชเชียร์ตรวจพร้อมภาพสลิป

⚠️ **เบราว์เซอร์ให้ใช้กล้องเฉพาะ `https://` หรือ `localhost`** คีออสก์ที่เปิด `http://192.168.x.x:8080`
จะขึ้น "เครื่องนี้ใช้กล้องไม่ได้" — ใช้ HTTPS หรือเปิด Chrome ด้วย
`--unsafely-treat-insecure-origin-as-secure=http://<ip>:8080`

⚠️ OCR พิสูจน์ได้แค่ว่า "ภาพดูเหมือนสลิปที่ถูก" ไม่ใช่เงินเข้าบัญชีจริง — สลิปปลอมที่ยอดและเวลาถูกจะผ่านโหมดอัตโนมัติได้
เปิดโหมดอัตโนมัติเมื่อวัดความแม่นกับสลิปจริงแล้ว (TODO A4)

## จอแสดงคิว (§22, §36)

`display.html` — ทีวีแขวนผนัง อ่านจากระยะ 3–8 เมตร **ไม่มีคนกด ไม่มีเมนู ไม่ต้องล็อกอิน**
แบ่ง **60% คิว / 40% เมนูแนะนำ** ตามสเปก · ต้องจับคู่เป็นอุปกรณ์ชนิด `DISPLAY` ก่อน

- คิวแบ่งสองคอลัมน์: **กำลังจัดเตรียม** กับ **พร้อมรับที่เคาน์เตอร์**
- ใบที่เพิ่งพร้อมจะกะพริบ 6 ครั้งพร้อมเสียงกริ่ง (§22 Flash Highlight, §31)
- ขนาดทุกอย่างอิง `vmin` — ทีวี 32"–55" และจอแนวตั้งใช้ไฟล์เดียวกัน
  (ที่นี่ใช้ `@media` ได้ ต่างจากคีออสก์ เพราะจอนี้กินทั้งหน้าต่างจริง ไม่ได้ถูก letterbox)

⚠️ **จอนี้ไม่ใช้ `/api/bootstrap`** และถูกกันออกจาก endpoint นั้นด้วย —
มันเป็นทีวีสาธารณะที่เสียบทิ้งไว้โดยไม่มีใครดูแล ไม่ควรถือยอดขายหรือรายชื่อพนักงาน
ใช้ `/api/display` ที่ส่งเฉพาะเลขคิวกับสถานะ **ไม่มีราคา ไม่มียอดเงิน ไม่มีชื่อคน**

🔔 **เสียงต้องกดเปิดครั้งเดียวตอนติดตั้ง** — เบราว์เซอร์บล็อกเสียงจนกว่าจะมีคนแตะจอ
ปุ่ม "เปิดเสียงเรียกคิว" จะหายไปเองหลังกด

## อาร์ติแฟกต์ไฟล์เดียว

```bash
python tools/build_kiosk_artifact.py           # สร้าง dist/cafeflow-kiosk.html
python tools/build_kiosk_artifact.py --check   # เทียบว่ายังตรงกับซอร์สไหม
```

อ่านไฟล์ชุดเดียวกับที่เว็บแอปใช้ แล้วต่อเป็นไฟล์เดียว — เขียนมือแยกอีกชุดแปลว่าพอแก้ราคา
ในแอปจริงแล้วเดโมจะโกหกลูกค้า · แทน `cf-store.js` ด้วย shim ในหน่วยความจำ (ไม่มี localStorage
ไม่มี sync ข้ามแท็บ) และตัด auth/print/export/navbar ออก

· stylesheet นอก Google Fonts — ผิดข้อไหน build ล้มทันที

**ข้อจำกัดที่ต้องรู้**: อาร์ติแฟกต์บล็อกรูปจากโดเมนภายนอก `imageUrl` จึงไม่ขึ้น
ระบบจะใช้ภาพวาดแทนให้เอง · ข้อมูลรีเซ็ตทุกครั้งที่เปิดหน้า

## โมเดลราคา: หนึ่งสินค้า หลายแบบเสิร์ฟ

ป้ายหน้าร้านมีสามคอลัมน์ **ร้อน / เย็น / ปั่น** และช่องที่เป็น `–` คือไม่มีขาย
สินค้าจึงเก็บราคาเป็น `prices: { HOT: 50, ICED: 50, FRAPPE: 70 }` — **คีย์ที่ไม่มี = ขายไม่ได้**
ไม่ใช่ราคา 0 ถ้าแปลงผิดตรงนี้ คีออสก์จะขายชาไทยโบราณแบบร้อนซึ่งร้านไม่มี

- อ่านราคาผ่าน `CFApp.priceOf(product, serveType)` เท่านั้น — ห้ามอ่าน `product.price` (ไม่มีแล้ว)
- `CFApp.serveTypesOf(product)` คืนแบบที่ขายได้จริง
- ของกิน (เบเกอรี่/อาหาร/ของหวาน) ใช้ `STD` ซึ่งคีออสก์จะไม่แสดงตัวเลือกให้เลือก
- `orderItem.serveType` ถูก snapshot ไว้พร้อม `unitPrice` ออเดอร์เก่าจึงไม่กระทบเมื่อแก้ราคา

**กฎตัวเลือก (§11)** ผูกกับ *แบบเสิร์ฟ* และ *หมวด* ไม่ใช่ผูกรายสินค้า — อยู่ใน `CFRules` (cf-app.js)
เย็น = หวาน+น้ำแข็ง+ท็อปปิ้ง · ปั่น/ร้อน = หวาน+ท็อปปิ้ง (ไม่มีน้ำแข็ง) ·
หมวดกาแฟ = +เมล็ดพิเศษ · หมวดมัทฉะ = +เกรดพิธีการ

## กติกาที่ต้องรักษาเมื่อเขียนหน้าใหม่

1. **ทุกการเขียนข้อมูลผ่านชั้น store เท่านั้น** ไม่มีหน้าไหนแตะ `localStorage` ตรง ๆ
   · โหมด `local` ใช้ `CFStore.mutate()` · โหมด `api` ใช้ `CFStore.cmd()` ที่ยิง endpoint
   แล้วดึงภาพจริงกลับมา — `mutate()` บนโหมด `api` จะโยน error ทันทีโดยตั้งใจ
   เพื่อให้จุดเขียนที่ยังไม่ได้แปลงโผล่ออกมาให้เห็น ไม่ใช่แก้เฉพาะในหน่วยความจำแล้วหายเงียบ
2. **ทุกการเปลี่ยนสถานะออเดอร์ผ่าน `CFOrders.transition()`** — เพื่อให้ผังสถานะและ audit log เป็นจริง
3. `render()` ต้อง **idempotent และไม่อ่านค่าจาก DOM** — view state อยู่ใน `this.state` ทั้งหมด
   เพื่อให้การเปลี่ยนแปลงจากแท็บอื่น re-render ได้โดยไม่ทำให้ tab/คำค้น/รายการที่เลือกหาย
4. เรียก `refreshIcons()` ท้าย `render()` และใน `Drawer.open({onOpen})` ทุกครั้ง
   แต่ **ห้าม**เรียกใน timer รายวินาที (มันเดินทั้ง document ทุก tick)
5. ปุ่มใน drawer ใช้ **inline `onclick`** — `Drawer` snapshot/restore ด้วย `innerHTML`
   ซึ่งไม่เก็บ handler ที่ผูกด้วย `addEventListener`
6. เพิ่มรายการ = **drawer** ไม่ใช่ modal · การพิมพ์ = **จำลองกระดาษใน drawer ก่อนเสมอ**
7. **หน้าคีออสก์ห้ามเรียก `CFApp.applyRoleGate()`** — ไม่มีผู้ใช้ล็อกอิน `getRole()` เป็น null
   ทุก element ที่มี `data-role-gate` จะถูกซ่อนหมด
7b. **`cf-kiosk-core.js` / `cf-kiosk-art.js` ถูกฝังในอาร์ติแฟกต์** จึงห้ามอ้าง `Drawer`,
   `showToast` ของ DS, `refreshIcons`, `CFAuth`, `localStorage` หรือลิงก์ `*.html` โดยตรง
   — `--check` บังคับข้อนี้เชิงกล
8. เปลี่ยนโครงสร้างข้อมูลเมื่อไหร่ **โหมด `local`** ต้อง bump `SCHEMA` ใน `cf-store.js`
   ไม่งั้นเบราว์เซอร์ที่มีข้อมูลเก่าจะไม่ seed ใหม่และพังเงียบ ๆ
   ส่วน **โหมด `api`** ใช้ migration ใน `db/migrations/` แทน (ไฟล์ที่รันไปแล้วห้ามแก้ —
   ตัวรัน migration ตรวจ checksum และจะล้มถ้าถูกแก้)
9. **ตรรกะที่เซิร์ฟเวอร์กับเบราว์เซอร์ต้องคิดตรงกันอยู่ใน `shared/`** (ผังสถานะ · สูตรราคา ·
   กฎตัวเลือก · ตารางสิทธิ์) — ห้ามคัดลอกไปไว้อีกฝั่ง จะเพี้ยนจากกันเสมอ

## หมายเหตุทางเทคนิค

**การ sync มีสามชั้นทั้งสองโหมด** — โหมด `local` ใช้ (`storage` event → `BroadcastChannel`
→ poll 1.5 วินาที) บน `localStorage` · โหมด `api` ใช้ (SSE → `BroadcastChannel` → poll 15 วินาที)
บนเซิร์ฟเวอร์ · **ชั้น poll คือชั้นที่ทำงานแน่นอนที่สุด จึงห้ามตัดทิ้งทั้งสองโหมด**
Safari บล็อก `localStorage` บน `file://` — ระบบจะถอยไปใช้หน่วยความจำและแจ้งเตือน (เดโมยังเดินได้ แค่ไม่ sync)

**วันที่ถูกเลื่อนอัตโนมัติ** ถ้าเปิดเดโมข้ามวัน `CFStore.init()` จะเลื่อน timestamp ทุกตัวไปทั้งวัน
ไม่งั้นจะเจอหน้าภาพรวมว่างเปล่าและตัวจับเวลา KDS เป็นหลักสิบชั่วโมง

**ไอคอน** navbar ใช้ inline SVG ใน `DS_ICONS` (กัน Lucide CDN ล่ม) ส่วนในเนื้อหน้าใช้
`<i data-lucide="...">` ตามปกติ — ออฟไลน์แล้วไอคอนในหน้าจะหายแต่ navbar ยังอยู่

**การพิมพ์** ใช้สูตร A ของ `ds-print.css` (`#dsPrintStage`) โดย `@page` ถูกฉีดตอน runtime
เพราะ `@page` เลือกด้วย body class ไม่ได้ และ `ds-print.css` มี `@page` ค้างอยู่สองชุด
`cf-app.css` เพิ่ม `display:none` ให้พี่น้องของ `#dsPrintStage` ด้วย — สูตร A ซ่อนด้วย `visibility`
ซึ่งยังกิน layout box ทำให้ได้หน้ากระดาษว่างตามหลังใบเสร็จ

**ใบปิดรอบพิมพ์ได้ 3 ขนาด** 58/80 มม. ได้ฉบับย่อ (สรุปยอด + ควบคุมเงินสด + ช่องเซ็น)
ส่วน A4 ได้ฉบับเต็มพร้อมตารางสินค้าขายดีและ KPI — ตารางหลายคอลัมน์ลงกระดาษ 48 มม. ไม่ได้

**58 มม. ไม่ใช่ 80 มม. ที่ย่อลง** พื้นที่พิมพ์จริงเหลือราว 48 มม. (~22 ตัวอักษร)
`cf-docs.js` จึงแยกเส้นทางการจัดบรรทัด: ที่ 58 มม. ชื่อสินค้าขึ้นบรรทัดของตัวเอง
และใช้ตัวย่อตัวเลือก — **ยกเว้นสลิปครัวที่สะกดเต็มคำเสมอ** เพราะครัวใช้ตัดสินใจผลิต
